# Assumptions and open questions

Decisions made during implementation where the brief was silent or ambiguous. Each item is marked **Open** until confirmed by the product owner. A1–A16 were confirmed by the product owner on 2026-11-03.

| # | Area | Assumption | Status |
| --- | --- | --- | --- |
| A1 | Invoice amount | "Invoice amount" is the **gross total including GST**. The optional GST field records the tax component contained in it. Financing is calculated on the builder-approved amount, which defaults to the invoice total. | Confirmed (2026-11-03) |
| A2 | Partial approval | Builders may approve a lower amount than invoiced (never higher). The discount applies to the approved amount. | Confirmed (2026-11-03) |
| A3 | One programme per builder | A builder can have only one **active** financing programme at a time, so the applicable rate is unambiguous. Activating a second one is refused until the first is suspended/closed. | Confirmed (2026-11-03) |
| A4 | Rate changes vs open offers | Changing a programme's terms withdraws (supersedes) any **un-accepted** offers priced on it; the CP regenerates to see current terms. Accepted requests keep their stored snapshot and are never repriced. | Confirmed (2026-11-03) |
| A5 | Offer validity | Offers are valid for the programme's `offerValidityDays` (default 7). Expired offers can be regenerated while the invoice remains eligible. | Confirmed (2026-11-03) |
| A6 | Financier rejection | A financing request rejected by Veefin is final for that invoice (no re-request), which also enforces one financing request per invoice. | Confirmed (2026-11-03) |
| A7 | Disbursement simulation | Disbursement is two explicit steps for realism: **Initiate** (instruction booked, reference generated) → **Confirm simulated transfer** (UTR generated, status DISBURSED). No bank integration exists. | Confirmed (2026-11-03) |
| A8 | Settlement | Settlement amount = builder-approved invoice amount, due on the invoice due date, or invoice date + empanelment credit period when no due date was given. NOT_DUE / DUE / OVERDUE are derived from the date; SETTLED is set manually by a Veefin user. | Confirmed (2026-11-03) |
| A9 | Eligibility | An accepted invoice is eligible for early payment only while its due date is in the future and an active programme exists for its builder. | Confirmed (2026-11-03) |
| A10 | Clarification loop | When a builder requests clarification, the CP responds with a note (and optionally a replacement PDF), which returns the invoice to the builder's inbox. | Confirmed (2026-11-03) |
| A11 | Organisation names | "Godrej Properties Demo" and "Prestige Realty Partners" are used as instructed and suffixed/marked as demo. No logos or proprietary assets are used; all identifiers (GSTIN, PAN, RERA, bank) are fictional. | Confirmed (2026-11-03) |
| A12 | GST on sample invoices | Sample brokerage invoices use SAC 997222 at 18% GST, split CGST/SGST for intra-state and IGST for inter-state supplies. | Confirmed (2026-11-03) |
| A13 | Deployment target | The database is PostgreSQL everywhere (local development through `docker compose up -d postgres`; hosted on a single server with Docker Compose, or RDS / Neon / Vercel Postgres). Uploaded PDFs use local file storage on a persistent volume; for multi-instance or serverless hosting they should move to object storage (S3 / Vercel Blob), because serverless and container file systems are not durable. The final target, region and domain need confirmation. | Confirmed (2026-11-03) |
| A14 | OCR assets | Tesseract.js runs in the browser; its WASM core and English language data are fetched from the public CDN on first use. Invoice documents themselves never leave the user's machine for extraction. | Confirmed (2026-11-03) |
| A15 | Users per organisation | Each demo user belongs to exactly one organisation. The data model supports multiple memberships for later. | Confirmed (2026-11-03) |
| A16 | Branch protection | `develop` requires a pull request and passing CI but **no approving review** (single-developer team for now); `main` requires a pull request from `develop`, passing CI and one approval. Raise the review requirement on `develop` when the team grows. | Confirmed (2026-11-03) |
| A17 | Hosted demo topology | The hosted demo runs on one Lightsail instance in `ap-south-1` with Docker Compose: Caddy (automatic HTTPS), the app, PostgreSQL and a nightly backup job, with daily instance snapshots. A multi-instance production topology on managed services is planned separately (docs/DEPLOYMENT.md, sections 1 and 3). | Open |
| A18 | AWS region and networking | Resources live in `ap-south-1` (Mumbai). Only ports 80 and 443 are public; SSH is limited to the office VPN egress address; PostgreSQL is reachable only on an internal Docker network. | Open |
| A19 | Deployment | Releases to the demo server are built on a workstation and loaded over SSH, then started with `docker compose up -d --no-build` (docs/DEPLOYMENT.md, section 5). An automated pipeline to the server is a later step. | Open |
| A20 | Demo data on hosted environments | The container applies migrations on every start and seeds only when the database has no users or `SEED_ON_START=true`. Demo data is otherwise kept across deployments; EFS backups are the recovery mechanism because migrations are forward-only. | Open |
| A21 | Container contents | The runtime image carries the production dependencies needed by the Prisma CLI, tsx and the seed (alongside the traced standalone server) so that it can migrate and seed itself without a separate migration image. Image size (about 1 GB uncompressed) is accepted for the demo. | Open |
| A22 | Automated test data | Vitest runs against the PostgreSQL database `brickflow_test` and Playwright against `brickflow_e2e` (overridable with `TEST_DATABASE_URL` / `E2E_DATABASE_URL`); both are dropped and recreated from the real migrations and seed on every run, and test files run serially because they share one database. Workspace sign-out in the smoke suite is skipped automatically while a workspace root has no page (HTTP 404) and runs once the portal pages exist. | Open |
